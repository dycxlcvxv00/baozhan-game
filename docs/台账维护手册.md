## 1. 连接仓库（第一步，不做完不许动代码）

> 铁律：任何要改仓库代码或数据的任务，开工前必须先证明「能连上仓库并读到真实内容」。
> 沙箱不跨会话持久 —— SSH key 会丢、本地仓库可能不存在、远端可能有新提交。

### 1.1 连 GitHub（用项目资产《GitHub 连接》）

跑《GitHub 连接》**第 0 步**一键脚本（写 SSH key + 硬编码 hosts + 锁 TLS1.2），验证：

```bash
ssh -T git@github.com        # 期望：Hi dycxlcvxv00! You've successfully authenticated...
```

### 1.2 拉代码

```bash
git clone git@github.com:dycxlcvxv00/baozhan-game.git /workspace/baozhan-game
cd /workspace/baozhan-game
git pull --rebase origin main   # 确认拿到远端最新，防止覆盖别人的提交
```

### 1.3 配令牌（AI 侧）

```bash
export BAOZHAN_TOKEN=github_pat_xxx     # 方式一：环境变量
echo -n "github_pat_xxx" > .gh_token    # 方式二：文件（已在 .gitignore）
```

令牌 = fine-grained，只需 `Contents: Read and write`，范围限 `baozhan-data`（页面用）；
代码仓提交走 SSH 或带 token 的 Contents API。

### 1.4 就绪自检（全过才算就绪）

| # | 检查 | 期望 |
|---|---|---|
| ① | `curl -s -H "Authorization: Bearer $BAOZHAN_TOKEN" https://api.github.com/user \| grep login` | `dycxlcvxv00` |
| ② | 远端关键文件与本地一致（字节数 + 特征串 grep） | 对得上 |
| ③ | `python3 tools/xp.py status` 记录数 | 与 §头部数据规模一致 |
| ④ | 探针文件写入再删除（无害验证写权限） | 成功 |

**任一项不符 → 说明仓库状态变了，先报告再动手，不许直接写入。**

### 1.5 失败处理

| 失败 | 处理 |
|---|---|
| 401 Bad credentials | token 过期 → 让用户重新生成 |
| clone 失败 / gnutls handshake | 跑《GitHub 连接》第 0 步；仍不行用 Contents API 逐文件重建工作区 |
| 记录数对不上 | 数据可能丢失或用户刚改过 → **停下来报告** |
| 403 Resource not accessible | token 权限不足 → 补 Contents: RW |

## 2. 架构速览

| 项 | 内容 |
|---|---|
| **代码仓库** | `dycxlcvxv00/baozhan-game`（公开，GitHub Pages 站点） |
| **数据仓库** | `dycxlcvxv00/baozhan-data`（**私有，唯一权威数据源**） |
| 数据文件 | `baozhan-data/data.json`（晶石）/ `baozhan-data/xp.json`（经验） |
| 晶石台账页面 | <https://dycxlcvxv00.github.io/baozhan-game/index-records.html>（可录入） |
| 经验台账页面 | <https://dycxlcvxv00.github.io/baozhan-game/index-xp.html> |
| 本地路径 | `/workspace/baozhan-game`（**不是** `/root/baozhan-game`） |
| 部署 | `git push` → Pages 自动构建（约 20–50 秒）；数据提交走 Contents API（`xp.py` / `repo_tool.py`） |
| 公开快照 | 本仓 `data.json` = 私有仓快照，供页面「仓库恢复」按钮（公开，用户已确认） |

**页面 ↔ 云端同步**：浏览器 localStorage 存令牌，改动后 1.2s 防抖自动推送；
冲突以 `savedAt` 较新者胜；节点不一致（node 机制）时**阻止推送**。

## 3. 维护要求（红线，违反会坏事）

### 3.1 纪律

1. **先连仓库再动代码**（§1 铁律）；凭记忆改代码 = 改本地副本，用户看不到任何变化。
2. **数据完整性 > 新功能**。改任何涉及记录的代码前，先跑回归测试
   （单测 200+ 项断言 + e2e，见详细版各节「测试」小节）。
3. **改完必须验证线上生效**，不能只看本地。Pages 有多节点，用新特征串全节点确认：

```bash
curl -s "https://dycxlcvxv00.github.io/baozhan-game/index-records.html?v=$(date +%s)" | grep -c "新特征串"
```

4. 提交信息写清楚改了什么；改动落在手册有章节的，**同步更新手册**（详细版 §11 变更日志）。
5. `/workspace` 会消失 —— **任何东西都要 push 回仓库才安全**。

### 3.2 口径红线（动代码前过一遍，细节见详细版对应章节）

| 口径 | 规则 | 详见 |
|---|---|---|
| 结算日 | **8 点分割**：today() 在 0~8 点返回昨天；记录归期同口径 | §3.3 |
| 异界产出 | **闭合反推自动算**，不许手填；手填框已撤 | §3.8 |
| 来源分桶 | 录剩余晶石时点「异界」按钮：亮=`dsrc:'dun'` 进异界桶，不亮=进市集/转入桶；**录入成功后按钮自动复位** | §3.11 |
| 转移 | 任意号→任意号，5% 手续费接收方承担；转出 100 实收 95；弹窗不列自己 | §3.9 |
| 负残差 | 余额净减 = 打造消耗（`craftInferred`），**不进收入桶** | §3.15 |
| `real` 字段 | 全链路透传，历史真 bug | §3.4 |
| 档位快照 | 记录取录入当刻 wealth/tier，防历史错挂新档位；日级 telescoping 只做一次 | §3.4.5 |
| node 节点 | 只保留每号最后一条基线；节点不一致阻止推送 | §3.12 |
| 仓库恢复 | 检测条数骤减等丢失特征会**拦截**，不静默覆盖 | §3.19 |

### 3.3 UI 红线（用户明确要求，别回退）

- 卡面 = v12 竖版卡牌 + **A 版「深空霓虹」配色**：卡片底 `#111827`、内部块 `#0a0e16`，**内部小框一律无描边**，只靠底色分区；卡片外框、铭牌分隔线、录入虚线 `dashed #3d4a5e` 保留。
- 卡宽下限 **340px**（`auto-fill minmax(340px,1fr)`），防开关行折行。
- 明细面板**全宽跨整行**、插在被点卡片排末尾、15 列 + 横向滚动、**多张可同开**。
- 录入区 4 格标签用语义色（出售=紫 / 现金=金 / 秘境=红 / 转移=亮紫罗兰），数值文字保持中性。
- 主题色：今天已录入 = 淡绿 `#3fb950`，未录入 = 灰白 `#9aa4b2`。

### 3.4 录入 SOP 精简版

**晶石台账（页面上直接填）**：

| 框 | 填什么 |
|---|---|
| 出售晶石 / 现金收入 / 秘境消耗 | 流水，照实填 |
| 转移晶石 | 填了必须点「转给 ▾」选目标号 |
| 剩余晶石 | 盘点值（填 0 也算有效录入） |
| 「异界」按钮 | 本次收入来自异界才点亮，录入后自动复位 |

推荐流程：代练只报「剩余晶石」→ 判断来源点亮/不亮异界按钮 → 录入，产出自动分桶。

**经验台账（一条命令）**：

```bash
python3 tools/xp.py add --map "空洞城寨" --tier T15 --mob-lv 88 \
  --qty 0 --stones 689 --cur 2114440142 --level 89
# 批量：每条加 --no-publish，最后 python3 tools/xp.py publish 一次性发布
```

## 4. 常见坑速查

| 坑 | 解法 |
|---|---|
| 页面显示旧版 | Pages 多节点有滞后，强刷 Ctrl+F5；确认提交已推送 |
| 本地改完 push 失败 | 跑《GitHub 连接》第 0 步重配 SSH |
| 记录数突然变少 | 数据可能被覆盖 → 停手报告；「仓库恢复」有护栏拦截 |
| 凌晨录入归错天 | 8 点分割，0~8 点归昨天（today() 已处理，别自己算日期） |
| 转移收入显示 0 | 转出号当天还没录 → 补录后自动带出 |
| 「异界产出」想手填 | 不许 —— 已撤，靠闭合反推；解释见详细版 §3.8 |
