## 2. 打图经验台账（index-xp.html）

### 2.1 数据区字段

记录写在 `const XP_RECORDS = [...]` 数组里，一条长这样：

```js
{ dt:'2026-09-27 21:09:00', role:'陌尘', level:86,
  map:'王城虫穴2层', tier:'T14', mobLv:86, mobQty:0,
  pot50:false, pot20:false, stones:595,
  prev:550179354, cur:567539061, note:'' },
```

| 字段 | 含义 | 取值规则 |
|---|---|---|
| `dt` | 打完图的**实际时刻** | `YYYY-MM-DD HH:MM:SS`，如实记录，**绝不因 8 点规则改写** |
| `role` / `level` | 角色名 / 角色等级 | 陌尘 / 86 |
| `map` | 地图名称 | 读截图 |
| `tier` | 地图阶级 | `T1`–`T19`，读截图 |
| `mobLv` | 怪物等级 | 读截图 |
| `mobQty` | 怪物数量加成 % | **面板显示值 + 词缀区各条之和**（两处叠加，纯数字）；无加成写 `0`；不确定写 `null`（显示 —） |
| `pot50` / `pot20` | 经验药水 50% / 20% | `true` = 吃了（显示 ✓） |
| `stones` | 本次晶石掉落 | **以用户消息中给出的数字为准**（截图里的晶石数字不采用） |
| `prev` | 上次经验值 | **必须等于上一条的 `cur`**（脚本自动取） |
| `cur` | 当前经验值 | 读截图 |
| `note` | 备注 | 如 `'狂暴'`，默认空 |

`const UPDATED_AT = 'YYYY-MM-DD HH:MM'` 需同步为最后一条的时刻（脚本自动改）。

### 2.2 计算规则

- 本图获得经验 = `cur − prev`
- 获得占当前等级% = 获得经验 ÷ 1,999,268,000
- 等级累计进度% = `cur` ÷ 1,999,268,000（与游戏 Exp 条一致）
- **86 级升级总经验常量 `LEVEL_TOTAL = 1,999,268,000`**。升级后要改这个常量。

### 2.3 8 点结算规则（双时间口径 —— 核心设计）

> **明细永远记实际时间，只在统计时才按 8 点归期。**

```js
function xpSettleDate(dt){
  // time < 08:00:00 → 归前一天；否则归当天
}
```

- 例：9-27 凌晨 01:40 打的图，明细里 `dt` 仍是 `2026-09-27 01:40:33`，但统计时归入 **2026-9-26** 结算日。
- 结算期 = 当天 08:00 → 次日 08:00。
- 与晶石台账的 `settleDateOf()` 是同一条规则，两边必须保持一致。

### 2.4 页面结构（自上而下）

1. **顶部栏**：角色 chip、已统计地图数、更新时间
2. **6 张汇总卡片**（累计口径）：当前等级 / 当前经验值 / 等级总经验 / 等级累计进度（带进度条）/ 累计获得经验 / 累计晶石掉落
3. **每日信息区**：**每个结算日一个独立折叠面板**，日期倒序（最新在最上）
   - 标题栏：`2026-9-27`（今天带青色「今天」标）+ 摘要 `N 张 · 经验 X · 晶石 Y`
   - 展开后：6 张当日卡片 + 「当日明细」表格
   - 当日卡片：当日打图数 / 当日获得经验（右上角橙色 `Lv.86` 标签）/ 当日占等级进度 / 当日晶石掉落 / 当日药水使用 / 当日结束进度（带进度条）
   - **当日明细序号从 1 重新开始**，按实际时间正序，表尾带当日小计
   - 默认：最新一天展开，其余折叠；折叠状态按天记忆（localStorage `xp-ledger-day-fold-<日期>`）
4. **全部明细**（默认折叠）：跨日全量 21+ 条，最新在最上，序号用全局 1…N
5. **T 级颜色图例**、**统计规则**

### 2.5 UI 设计约定（用户明确要求，别回退）

- 卡片**没有底部灰色副标题**（`.s` 已全部删除）
- 日期简写为 `2026-9-26`（去前导零），不写 `08:00 → 次日 08:00` 那一长串
- 明细**必须在每日面板内部**，折叠面板即隐藏明细

## 3. 角色晶石台账（index-records.html）

### 3.1 数据在哪

- 数据存在**浏览器 localStorage**（键 `LS_KEY`），用户直接在页面上录入。
- 页面支持通过 GitHub API（`api.github.com/repos/.../contents/data.json`）做云端同步，需 token。
- **AI 通常不需要改这个文件的 `ACCOUNTS` 数据**，只在改逻辑/修 bug 时动代码。

### 3.2 录入字段（页面表单）

账号（必填）、角色名、职业、等级、财富、初始存量晶石；每次录入填：当前剩余晶石 / 当日出售 / 出售收入 / 人工成本 / 混沌成本。

### 3.3 时间口径（与经验台账同一条规则）

```js
// 写入：如实记录实际时刻
rec = { date: nowDate(), time: nowTime(), real: 1, ... }
// 统计：8 点归期
settleDateOf(r) = (r.time < '08:00:00') ? r.date - 1天 : r.date
```

**历史记录无 `real` 标记**的，沿用已写入的 `date` 原值，保证老数据不变。

### 3.4 名字变绿逻辑

`recordedToday(c)` = 该角色是否存在 `settleDateOf(r) === today()` 的记录。
凌晨录入（8 点前）会归到前一天——toast 会提示「凌晨时段，计入 X」，这是**正确行为**，不是 bug。

## 4. 标准录入 SOP（提速版）

### 4.1 单条录入 —— 一条命令搞定

用户发来截图 + 晶石数（如「595」）后：

```bash
cd /root/baozhan-game && python3 tools/xp.py add \
  --map "王城虫穴2层" --tier T14 --mob-lv 86 --qty 0 \
  --stones 595 --cur 567539061
```

脚本自动完成：取上一条 `cur` 作 `prev` → 追加记录 → 改 `UPDATED_AT` → `node --check` → commit/push → 轮询验证 → 同步 `/workspace` → 重生成 Excel。

### 4.2 连续多条 —— 批量提交（**最省时间**）

用户常一次连发好几张图。此时**不要每条都发布**：

```bash
# 第 1 条：只写本地
python3 tools/xp.py add --map "贫民窟" --tier T14 --mob-lv 86 --qty 55 --stones 615 --cur 359939306 --no-publish
# 第 2 条：只写本地
python3 tools/xp.py add --map "破灭堡垒" --tier T12 --mob-lv 82 --qty 15 --stones 576 --cur 384179245 --no-publish
# 最后一次性发布
python3 tools/xp.py publish
```

**N 条记录只等一次 Pages 生效。**

### 4.3 极速模式

`add --no-publish --no-wait` 然后统一 `publish --no-wait`：完全不等线上生效，事后用户 Ctrl+F5 即可。
代价：不确认部署成功。**只在用户明确追求速度时用。**

### 4.4 从截图提取字段的要点

> **最高优先级规则：用户消息里发的数字 = 本次晶石数量，直接采用，不要从截图里读晶石。**
> 用户会单独发一个数（如「595」），那就是 `stones`。截图里的晶石相关数字（面板值、掉落记录「灵魂晶石\*567」等）**仅供参考，一律不覆盖用户输入**。
> 已在 2026-09-27 全量核对：#10–#22 共 13 条，记录的 `stones` 与用户输入的数字**完全一致**，无修正项。

| 要读的 | 来源 | 注意 |
|---|---|---|
| **晶石数量** | **用户消息里的数字**（最高优先级） | 截图里的晶石数字不看、不比对、不质疑 |
| 地图名 + 阶级 | 截图顶部地图信息，如「虚无异界地图·单人 阶14 → T14 王城虫穴2层」 | 阶14 = T14 |
| 怪物等级 | 截图地图信息面板 | 与角色等级不同 |
| 怪物数量 % | **面板值 + 词缀区各条之和（两个地方叠加，不是二选一）** | 例：面板 +57%、词缀三条 +25%（共 75%）→ 记 **132**。见下方「怪物数量计算规则」 |
| 当前经验值 | 截图经验条上方数字 | 这是 `cur` |
| 药水 | **状态栏红/白药水图标**（见下方规则）/ 用户说明 | 用户说「吃了 50 和 20」时两个都 true，**用户口述优先** |

#### 经验药水识别规则（用户 2026-09-28 明确）

> 状态栏（底部技能条上方那一排增益图标）里：
> **红色药水 = 20% 经验药水**，**白色药水 = 50% 经验药水**。

- 图标在状态栏里亮着 = 该药水**本次生效** → 对应字段置 `true`
- 两者同时亮 = 双药水叠加 → `pot50:true, pot20:true`（例：#30 冥河河畔）
- 截图不明显时，以用户口述为准（如「刚才也是 50 20 的药水生效」）

#### 怪物数量计算规则（用户 2026-09-27 明确）

> **面板显示的怪物数量% 与词缀区的「怪物数量增加 X%」是两个独立来源，必须相加，不是二选一。**

- 示例（#27 破灭堡垒）：面板 `+57%`，词缀区三条 `+25%`（25×3 = 75）→ `mobQty = 57 + 75 = 132`
- 示例（#20 王城虫穴2层）：面板 `+36%`，词缀 `+45%` → `mobQty = 81`（原记录 81 已符合此规则）
- 若一眼看不出面板值来源，把面板值与词缀和都写进 `note` 备查，如 `'怪物数量 57(面板)+75(词缀)'`

## 5. 为什么以前慢 + 已做的优化

### 5.1 耗时拆解（旧流程 ≈ 90–120 秒 / 条）

| 环节 | 旧做法 | 耗时 |
|---|---|---|
| 编辑数据 | 手工 Edit 记录 + Edit `UPDATED_AT` | 2 次工具调用 |
| 语法检查 | 单独 Bash 跑 `node --check` | 1 次调用 |
| Excel 同步 | 手工改 `make_xp_table.py` 的 records 列表再跑 | 1–2 次调用，**易错** |
| git commit/push | 单独 Bash | 1 次调用 |
| **等 Pages 生效** | **固定 `sleep 80`** | **最大瓶颈，且常常白等** |
| 线上验证 | 下载全文 sha256 对比 | 1 次调用 |

### 5.2 优化后（≈ 30–40 秒 / 条，批量更快）

| 优化点 | 做法 | 效果 |
|---|---|---|
| **轮询替代固定等待** | push 后静默 8s，之后每 10s 请求一次，命中指纹即停（最多 150s） | 实测生效 **28.4s** 就返回，比 `sleep 80` 省 **~50s** |
| **一键脚本** | `xp.py add` 把 6 个步骤合并 | 工具调用 **7 次 → 1 次** |
| **Excel 自动生成** | 直接从 HTML 解析 `XP_RECORDS` 生成，与手工版**逐格零差异**（已验证） | 彻底消除双份数据维护 |
| **批量提交** | `--no-publish` 累积 + 一次 `publish` | N 条只等一次 |
| **快失败切换 IP** | curl `--max-time 10`，一个节点慢立刻换下一个（108 → 109 → 110） | 避免单次卡 20s+ |

**实测**：2026-09-27 21:16 的 publish 全流程 **33.9 秒**（push + 生效 28.4s + Excel + 同步）。

### 5.3 还能更快吗

- 用户的截图 → 字段提取是纯 AI 推理，占大头且必要，**不要为了减少步骤而跳过语法检查或验证**。
- 想再快只有 `--no-wait`（省掉全部等待，约 5 秒结束），但失去部署确认。**不推荐默认使用。**

## 7. 常见坑与排错

| 现象 | 原因 / 处理 |
|---|---|
| 刷新后看不到新内容 | GitHub Pages / CDN 缓存，让用户 **Ctrl+F5** 强刷 |
| `curl` 返回 HTTP 000 | 该 CDN 节点偶发失败，脚本已自动轮询 `185.199.108.153 / 109.153 / 110.153`，无需手动处理 |
| `gh api` 报「please run gh auth login」 | **gh 未登录**，不要用 `gh api` 查 Pages 构建状态；改用 curl 抓页面内容比对 |
| 当日卡片数字不对 | 检查 `dt` 是否落在 8 点前（归前一天）；明细时间本身**不要改** |
| 经验值对不上 | `prev` 必须严格等于上一条 `cur`；脚本自动保证，别手改 |
| 名字不变绿（晶石台账） | 凌晨录入归前一天是**正确**的；若当天 8 点后录入仍不绿，检查 `settleDateOf` |
| Excel 与页面不一致 | 只能由 `xp.py excel` 生成，禁止手改 xlsx |
| 微信/剪贴板截图读不出 | 路径 `/root/uploads/wb-img-*/Clipboard_Screenshot.png`，用 Read 工具查看；若模型不支持图片，请用户换多模态模型或口述数值 |
